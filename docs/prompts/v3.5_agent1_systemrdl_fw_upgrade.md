MỤC TIÊU: NÂNG CẤP AGENT 1 - CHUẨN HÓA SYSTEMRDL, FIRMWARE DRIVER & COCOTB REG MODEL (VERSION 3.5)
Hệ thống Agent 1 V3.0 đã hoàn thiện. Bây giờ, với tư cách là Principal Architect, tôi yêu cầu bạn nâng cấp Agent 1 lên Version 3.5. Đợt nâng cấp này tập trung vào tính tương tác với Đội lập trình nhúng (Firmware) và Đội kiểm thử (DV) bằng các chuẩn công nghiệp thực tế.
[QUY TẮC SỐ 0 - LƯU VẾT PHIÊN BẢN (VERSION CONTROL)]:
Tuyệt đối chưa sửa code! Việc ĐẦU TIÊN bạn phải làm là tạo một file tên là docs/prompts/v3.5_agent1_systemrdl_fw_upgrade.md. Hãy chép nguyên văn toàn bộ nội dung yêu cầu này của tôi vào file đó để lưu trữ lịch sử nâng cấp hệ thống.
[NHIỆM VỤ 1 - TRIỂN KHAI CÁC TÍNH NĂNG MỚI (IDEAS)]:
1. Nâng cấp Memory_Map_Interface_Expert (Chuẩn hóa RDL):
Không chỉ xuất JSON, BẮT BUỘC sinh thêm file đặc tả thanh ghi theo chuẩn công nghiệp SystemRDL 2.0 (agent1_register_map.rdl).
File RDL phải có đủ các thuộc tính phần cứng: reset value, access mode (rw, ro, w1c), hw/sw mask.
2. Nâng cấp HW_SW_CoDesign_Expert (Sinh Firmware Skeleton):
Phải tự động dịch file Memory Map thành 2 file cho đội Phần mềm (Firmware):
fw_<project_name>_regs.h: Chứa các #define Base Address, Register Offsets, và Bitmasks.
fw_<project_name>_driver_stub.c: Sinh ra một bộ khung (skeleton) hàm C cơ bản để Read/Write các thanh ghi (VD: hàm init(), hàm clear_interrupt()).
3. Nâng cấp Verification_Strategy_Expert (Sinh Cocotb Register Model):
Trong ngành vi mạch, Testbench phải dùng UVM Register Model. Hãy yêu cầu Expert này sinh ra một file Python: tb_<project_name>_reg_model.py.
File này mô phỏng lại toàn bộ map thanh ghi dưới dạng các class Python để sau này Agent 3 (DV) dùng Cocotb gọi thẳng tên thanh ghi thay vì hardcode địa chỉ Hex.
[NHIỆM VỤ 2 - CẬP NHẬT MA TRẬN KIỂM TRA CHÉO (CROSS-VALIDATION)]:
Việc sinh thêm nhiều file rất dễ dẫn đến việc các file không khớp nhau (Ví dụ file .h có offset là 0x04 nhưng file .py lại là 0x08). BẮT BUỘC thêm 2 Validator mới vào LangGraph:
Cross-Check D (RDL_vs_CHeader_Validator): Cảnh sát Firmware. Bắt buộc kiểm tra chéo file JSON/RDL với file .h. Nếu phát hiện định nghĩa địa chỉ sai lệch hoặc thiếu hàm Reset, đánh lệnh REJECT ép HW/SW Expert viết lại.
Cross-Check E (RDL_vs_DVModel_Validator): Cảnh sát Verification. So sánh file JSON/RDL với file reg_model.py. Nếu thiếu Register nào trong Test model, đánh lệnh REJECT ép Verification Expert viết lại.
[NHIỆM VỤ 3 - KIỂM THỬ UAT (TỰ ĐỘNG)]:
Sau khi cập nhật mã nguồn cho LangGraph (thêm Experts và Validators mới), hãy tự động chạy Partial Run (chỉ Agent 1) bằng file debug_runners/run_partial.py với yêu cầu:
"Thiết kế lõi mã hóa phần cứng AES-128. Phải có thanh ghi KEY (Write-Only) và thanh ghi STATUS (Read-Only)."
Hãy tự assert xem các file .rdl, .h, .c và .py đã được đẻ ra đủ trong thư mục reports/agent1/ chưa, và in báo cáo PASS/FAIL ra Terminal.
